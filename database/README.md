# 数据库迁移说明

唯一执行源为 `backend/src/main/resources/db/migration/V1__initial_schema.sql`，避免复制SQL产生漂移。采用MySQL8.0/InnoDB/utf8mb4及Flyway版本迁移。由受控数据库账号预先创建空库 `study_room_reserve`，启动后Flyway创建六张业务/支撑表和版本记录，JPA只验证结构。重复启动不会重建表，不执行drop；不要编辑已应用迁移，未来变化追加V2及后续迁移。

应用账号需在目标库具备迁移所需DDL和日常DML权限；部署可另用迁移专用账号。生产默认没有演示密码和合成数据。必须主动设置`DEMO_SEED=true`才创建合成账号/房间，不覆盖同学号已有数据。禁止对原始课程SQL建成的已有库直接启用baseline；先备份并评估迁移，不静默替换用户数据。

约束包括学号/房号唯一、外键、合法状态和时间窗口、正容量、每单最多一条活动违规。`active_order_id`活动时等于订单ID，撤销置null；唯一索引同时允许多条已撤销历史。时间区间重叠不能由普通唯一键解决，由事务学生行→房间行→订单行悲观锁保障；重复请求按状态幂等，事务异常回滚整个状态/证据/计数/审计。

备份恢复由数据库运维工具执行；本项目没有自动删除或恢复生产库的脚本。H2仅用于显式demo/test profile，不替代真实MySQL验证。
