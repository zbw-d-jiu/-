## 3. 预约、权限与资源规则

R01：用户注册固定STUDENT；管理员通过受控初始化方式准备。服务端验证权限和归属，学生只能创建自己的预约、查自己的订单/违规、取消自己的订单。注册/资料更新不能改变role、violateCount、isBan。管理员不得借通用资料接口提权或直接任意改计数。

R02：预约日期满足 `today ≤ orderDate ≤ today+7`，当天仅允许开始时刻严格晚于服务器当前时间；这意味着今天剩余时段加后续7个自然日。开始与结束同一天，满足 `08:00 ≤ startTime < endTime ≤ 22:00`；不接受零长度、反向、跨午夜和不完整参数。最小可表达时长1分钟，不强制30/60分钟档位。时间窗口以服务器Asia/Shanghai计算。

R03：区间 `[start,end)`，重叠条件为 `existing.start < requested.end AND requested.start < existing.end`。相邻10:00—11:00与11:00—12:00不冲突；相等、包含、被包含、部分交叉都冲突。同房间不同学生、同学生不同房间两维均需在并发情况下成立。不能仅以应用层“先查询无冲突再插入”代替事务并发控制。

R04：冲突占用口径按所有非CANCELLED订单计算，NO_SHOW不主动释放原预约时段；只有合法取消释放。此口径防止爽约后重订使非取消订单分钟和超出房间可用分钟，且保证爽约误判恢复不产生冲突；主 agent 已采纳并同步开发，属于首版工程默认，不代表已经实现或验证。

R05：学生取消只允许自己的RESERVED且 `now < start`；恰好开始和开始后拒绝。管理员带原因可异常取消RESERVED，包括开始后；COMPLETED、NO_SHOW不能取消，违规误判走撤销。重复取消返回已取消状态，不重复改审计或发生费用等额外副作用。取消后保留订单、到场证据和已有违规，违规是否误判必须独立审查。

R06：关闭/软删除房间前，如存在 `status=RESERVED AND end>now` 的预约则拒绝，包括尚未开始和正在使用；管理员先按规则处理预约。软删除不物理删除历史，不级联丢订单/违规。OPEN房间可预约；CLOSED/软删除不可新增预约。房间展示信息更新不修改已有订单时间。关闭/删除与新预约并发必须保持“已关闭/删除资源不产生新有效单”的最终一致约束。

R07：累计活动违规≥3即isBan=true，只禁止新增预约；继续允许登录、查询、修改本人资料及取消符合时间条件的原订单。已有预约不自动取消。计数不是历史违规行数，而是未撤销记录数。管理员不得直接绕过阈值解封；撤销误判后重算，小于3才恢复新增预约权限。

## 4. 到场、状态和证据

预约创建为RESERVED/UNKNOWN。`status` 表示订单生命周期，`attendance` 表示到场分类，两者不能互相替代。

- 到开始时刻后，管理员可带reason确认ARRIVED、LATE或NO_SHOW。ARRIVED和LATE均记录服务器arrivedAt；LATE产生一次迟到违规。NO_SHOW没有到场时间，并产生一次爽约违规。
- 分类依据管理员实际核实，不由系统根据“超过开始时间”推断。首版没有自动判断迟到的分钟阈值；管理员必须写说明。UNKNOWN无论过期多久均不得定时全量改爽约。
- COMPLETE仅可用于有ARRIVED/LATE证据且 `now≥end` 的RESERVED订单，记录completedAt并改COMPLETED。已到场不能再改判NO_SHOW；已取消不可确认；无到场证据不可直接完成。
- 相同动作重试幂等，保留首次事件时间。单订单最多一个活动违规；处罚、订单状态、用户计数/封禁与审计必须在一致的事务边界内完成，失败不得只留下部分结果。
- 撤销违规保留原记录和撤销审计；撤销LATE保留到场并改ARRIVED，保留已完成/已取消生命周期；撤销NO_SHOW恢复RESERVED/UNKNOWN。重新分类须使用合法管理员动作，不能复活已撤销违规行。过期恢复只表示历史纠错，不授权学生预约过去时段。

## 5. 每日统计口径和算例

报表日期D以预约的orderDate归属。首版没有历史开放日历，因此采用**配置开放分钟分母**，不能将其称为精确历史实际营业分钟：参与报表的房间为当前未删除房间，以及D日有订单的已删除房间；关闭房间仍参与，每间默认840分钟。无订单的已删除房间不参与。当前关闭/删除和配置变更会影响历史报表，此为首版已知限制；后续需要房间生效日期和逐日开放快照才能精确还原历史。

- `totalRooms`：上述参与房间数量；`totalOrders`：D日非CANCELLED订单数；`totalViolations`：关联D日订单的未撤销违规数，不按执行确认的日期分组。
- `reservedMinutes`：D日所有非CANCELLED订单与当日开放窗口交集的分钟和，包含RESERVED、COMPLETED和NO_SHOW。取消不计预约量，爽约曾占用的时段计预约量。
- `usedMinutes`：仅D日COMPLETED且attendance为ARRIVED/LATE，同时arrivedAt、completedAt均存在的订单；使用区间取 `[arrivedAt,completedAt)` 并与订单区间及当日开放窗口相交，再求分钟和。到场但未完成暂不计，UNKNOWN/NO_SHOW/CANCELLED不计。此为管理员事件所支持的使用估计，不是传感器测量。
- 房间预约率=`100×reservedMinutes/availableMinutes`；使用率=`100×usedMinutes/availableMinutes`。总率先汇总全部分子、分母再相除，不能平均各房间百分比。分母0时返回0，显示无可统计开放时长。计算保留秒级精度，最后统一按2位小数四舍五入。

合成算例：A/B各开放08:00—22:00，共1680分钟。A有09:00—11:00已完成预约，管理员确认ARRIVED于10:00、完成于11:00，预约120分钟、使用60分钟；B有12:00—13:00爽约60分钟；另有取消单不计。则有效订单2、活动违规1，总预约率180/1680=10.71%，使用率60/1680=3.57%；A为14.29%/7.14%，B为7.14%/0%。本算例采用管理员人工分类而非系统按时刻自动推断迟到；若A被确认LATE，则活动违规总数相应为2，分钟及率不变。只有UNKNOWN订单时使用率必须为0。
