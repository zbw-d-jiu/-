## 工程与运行

Java21，Spring Boot3.5.16，Maven3.9.9，Spring Web/Validation/JPA，BCrypt，MySQL8.0，Flyway。无Lombok。正式默认MySQL，JPA `validate`；不建默认管理员，不启用演示密码。由受控账号先创建空数据库，再提供环境变量：

```powershell
# 本机合成环境由主agent生成ignored配置；禁止打印或提交密码。
. ./.data/mysql.env.ps1
& .tools/apache-maven-3.9.9/bin/mvn.cmd -B -ntp -f backend/pom.xml -DskipTests package
& java -jar backend/target/study-room-0.3.0.jar
```

部署时设置`DB_URL`、`DB_USERNAME`、`DB_PASSWORD`；默认HTTP8080，可设`PORT`。数据库URL需使用Asia/Shanghai。仅本机开发CORS允许localhost/127.0.0.1:5173；生产可由同源反向代理或把前端dist复制至`backend/src/main/resources/static/`后重新构建，不能把`history`路由当成自动存在的服务端映射。

公开GET `/api/health`，其余除登录注册外均需Bearer。合成演示可主动设置`DEMO_SEED=true`连接合成MySQL，或使用`--spring.profiles.active=demo`选择H2内存库。两种方式都创建`admin / Admin123!`和`20260001 / Student123!`、三间合成房间，不覆盖已有同学号。正式环境禁止开启此开关。H2 demo进程退出数据丢失；真实持久化验收必须用MySQL。

## 结构、权限和一致性

`ApiController`只做白名单DTO校验及响应包装；`BookingService`完成权限、事务、状态、统计；`Model`实体不直接序列化。Jackson拒绝额外字段，注册强制STUDENT。密码仅BCrypt哈希持久化，不返回密码或哈希。32随机字节Bearer令牌仅SHA256摘要入库，16小时有效，注销删除当前会话。没有真实校园身份认证，账号仅课程演示。

MySQL表含用户、房间、订单、违规及会话、追加审计。所有字段中文注释、外键、状态/容量/窗口检查约束；索引支持学生与房间时间冲突查询。房间软删除，状态取消、完成、爽约不物理删除。Flyway V1初始化、V2扩容审计理由，V3将全部历史/现有房间容量统一30并增加检查约束；V1/V2已应用文件不改。重复启动验证校验和且只执行新版本，不执行drop。已有原始课程表的数据库需另行备份、评估迁移，本实现不静默baseline。

并发预约使用事务内学生行→房间行悲观写锁；修改/取消/管理员到场/违规撤销采用学生→房间→订单锁序。关房/删房只获取房间锁，不再反向获取学生锁，避免反向锁序。学生重叠判定仍采用半开区间：existing.start<new.end且existing.end>new.start，同学生即使在不同房间仍不得重叠；仅CANCELLED释放占用，NO_SHOW/COMPLETED也占原区间。使用READ_COMMITTED避免鉴权读取产生早期快照后，锁等待结束仍读到旧违规计数；锁本身才是防并发冲突机制。锁超时返回409可重试，不报告成功。跨进程同一数据库也通过行锁协调。

共享房间每个订单占1个名额。在持有房间写锁的事务中，把已有非取消订单裁剪到候选区间，排序所有开始(+1)/结束(-1)事件，同刻先处理结束。取扫描过程中同时人数峰值，峰值小于30才新增，检查与插入保持在同一事务。不能直接count所有重叠行数：例如15人09:00—10:00、另15人10:00—11:00，与09:00—11:00重叠30行但同时峰值只有15，仍可再预约。取消也持同房间锁，防止名额释放/新增竞态。新建或修改房间的capacity仅接受30，Bean校验及服务再次验证，数据库V3提供兜底。

Room响应新增`occupiedSeats`与`remainingSeats`。完整合法日期/起止时间查询时，occupiedSeats为整个查询区间同时占用峰值，remainingSeats=30-峰值，是可覆盖整个区间的保守名额，不是逐时点名额相加。available要求OPEN且剩余大于0；无完整筛选的列表、详情、新建/修改响应两个名额字段为null，available只表示开放。列表是查询瞬时快照，提交时后端再次加锁检查。

同单违规写入由订单锁串行；`active_order_id`活动时等于order_id，撤销后null，数据库唯一键兜底每单最多一个活动事件。撤销历史保留，可追加新证据而不复活旧行。违规写入/撤销、状态变化、计数与>=3封禁、追加审计在同一事务，异常回滚。封禁只限制新增，不自动取消既有单。相同合法管理员动作及取消/撤销幂等，不重写首次时间或重复审计。已取消订单拒绝到场动作。

管理员开始后确认ARRIVED/LATE/NO_SHOW，原因必填；LATE和NO_SHOW创建违规。结束后且有到场证据才可COMPLETE，记录服务器真实completedAt。没有定时全体判爽约任务。撤销迟到保留arrivedAt并改ARRIVED，撤销爽约恢复RESERVED/UNKNOWN；过去恢复只用于纠错，不允许创建过去预约。上海Clock可在测试以`@Primary`固定Clock替换。每日08:00—22:00为首版固定工程窗口，`app.booking-days`可配置预订天数，调整窗口需同步SQL/统计/前端和验收，不能只改单一常量。

## 统计与当前边界

参与房间为当前未删除全部房间（含CLOSED）及选日有任意历史订单的deleted房间。统计升级为**人分钟**：每间分母为840开放分钟×30人=25200人分钟。保留字段名`reservedMinutes`、`usedMinutes`、`availableMinutes`兼容前端，但语义分别为预约人分钟、证据使用人分钟、可用人分钟。每个单人订单贡献相应分钟后求和，因此30人共同预约60分钟贡献1800人分钟，而非仅60分钟；房间预约率为1800/25200×100=7.14%。

有效订单数不含取消，活动违规按关联orderDate分组。预约人分钟含非取消订单，使用人分钟仅COMPLETED且ARRIVED/LATE，计算每单真实[arrivedAt,completedAt)与预约和开放窗口交集；保留小数分钟，最终率四舍五入2位小数且零分母0。总率先合并全部人分钟分子和25200×参与房间数的分母，不平均房间百分比。V3不改历史订单，因此历史旧版单人订单也按新的固定30人分母解释，旧报表百分比不继续沿用独占分母。

这是管理员事件支持的使用估计，没有传感器测量。没有历史开放日历，当前房间状态和删除状态可影响历史分母。首版全量列表不分页，适用于合成课程演示规模；没有声称性能或生产部署达标。API按{success,data,message}统一回应400/401/403/404/409/500，内部错误不回传SQL和堆栈。
