# 前端运行与交互

版本0.03；DEV-T04—T10；开发角色 gpt-6.1-sol / medium。采用 Vue2.7.16、Element-UI2.15.14、Vue Router3.6.5、Vite7.3.7，未迁移到 Vue3。入口 `frontend/src/main.js`，页面 `App.vue`，认证及统一请求 `api.js`，角色导航 `router.js`，响应式视觉 `style.css`。

## 安装与启动

使用 Node.js 20.19+ 或 22.12+（本轮实际 Node24.19.0）和 npm，项目仅保留 `package-lock.json`，不同时维护 pnpm 锁文件。在 `frontend` 目录执行：

```powershell
npm ci
npm run check
npm run build
npm run dev
```

首次尚无锁文件时运行 `npm install` 生成锁文件，再使用 `npm ci`。开发端口固定5173，地址 `http://127.0.0.1:5173`，`/api` 代理至 `http://127.0.0.1:8080`。生产构建输出 `frontend/dist`，部署时需配置同源 `/api` 反向代理到后端；Hash路由无需服务器对页面路径做回退。后端和 MySQL 启动方式见根 README。构建和自检脚本失败会以非零退出。

## 使用步骤

学生登录后选择日期、开始和结束时分，点击“查询时段”，再预约空闲房间。时分允许一分钟粒度，不限制半小时档；表单提供08:00—22:00窗口，后端复核今天至未来7个自然日、开始严格未来、同学生和同房间重叠。房间容量仅展示，预约为整间独占。改变时段将清除旧的查询依据，必须重新查询才能预约。“我的预约”取消尚未开始记录；“我的违规”展示有效和撤销历史及权限说明；“个人资料”仅修改姓名与联系方式（可为空）。

管理员导航包含数据总览、房间管理、预约管理、学生账号、违规纠错和个人资料。预约开始后才展示到场、迟到和爽约确认；已到场不可改爽约，已到场且结束后才能完成。管理员到场/迟到/爽约/完成、异常取消、撤销误判均要求填写原因。关闭或删除房间时如存在尚未结束的有效订单，后端拒绝；删除历史房间采用软删除保留历史。有效累计违规达到三次自动限制预约，撤销纠错后低于三次自动恢复；界面没有任意封禁/解封按钮。

统计完全取自真实 API，预约率与使用率为百分数，分钟和分母原样展示。按PO基线，关闭与历史软删除房间均在当日统计范围内，每间分母840分钟；实际使用按到场至完成区间裁剪到订单及当日开放窗口。没有完成证据的订单不生成使用时长。界面无静态伪造趋势或业务列表。

## 会话、权限与异常

只将令牌保存在 localStorage，用户信息保存在内存。受保护导航恢复会话时调用 GET `/api/auth/me`，每页加载及业务变更后再次刷新当前用户，避免旧的累计违规/封禁状态。学生/管理员菜单和路由隔离，真正的权限、所有权与一致性仍由后端执行。注册不发送role，资料不发送计数或封禁。接口采用统一 `{success,data,message}`；非2xx优先显示服务端message，网络错误提示检查服务，401清理会话并回登录，403/409清楚展示失败原因。提交设置busy防重复点击，房间查询以及管理员操作成功后重新从API加载状态。

列表提供加载、空结果、错误和重试；最新页面请求用版本号避免旧请求覆盖快切后的页面。登录密码提交后清空，不显示密码或哈希。演示账号默认折叠，仅注明合成演示数据，须后端初始化成功后使用。桌面左侧导航在窄屏转为顶部滚动导航，表格可横向滚动保留字段。

## 开发自检与测试交接

`npm run check` 检查全部Vue模板及JS语法，`npm run build` 检查实际Vite编译；两者属于开发自检，不替代独立测试或业务验收。首次调用npm run check因shell PATH中没有node失败，未将该尝试记作通过；修正PATH后执行结果见下方追加记录。

独立测试需启动真实后端、MySQL及演示数据，覆盖学生注册/登录/编辑、房间查询/预约/取消、页面刷新恢复会话、管理员维护与证据事件、违规撤销和统计。重点检查401回登录、403越权、409冲突提示、封禁状态刷新、表单改时段后不能使用旧查询、整分钟边界、对话框取消不发写请求、快速切页不串数据及小屏表格。真实双角色联调、网络中断和浏览器交互应记录实测结果，不依据界面代码存在判定通过。

### PO反馈的密码与时区边界修正

密码登录/注册共用校验：至少8个字符，`TextEncoder`编码后的UTF-8最多72字节，不按72字符误判断，不截断用户密码；24个汉字（72字节）通过、25个汉字（75字节）拒绝。服务端继续作最终输入校验。

`src/time.js`集中处理上海日期和订单绝对时刻。今日与+7日使用UTC+8计算，搜索、取消及到场/完成按钮将订单日期及时分明确解析为`+08:00`。日期选择器传入的Date仅取其本地日历年月日，再与上海日期字符串比较；不将日期组件本地零点当成上海业务零点。客户端时钟可能有偏差，前端提示和按钮只是交互辅助，服务器时钟决定写请求合法性。首版未来7个自然日的工程默认保持；如调整后端`bookingDays`，必须同步日期选择器、提示及边界检查，本轮未增加配置API。

`scripts/check-domain.mjs`以固定时钟验证上海跨日/跨月、订单`+08:00`绝对时刻、+7包含/+8拒绝、ASCII及汉字密码UTF-8上限；分别在UTC、America/Los_Angeles、Asia/Shanghai子进程运行日期组件边界。不修改用户系统时区，不依赖MySQL，不代替独立测试或后端验证。该检查已接入`npm run check`。
